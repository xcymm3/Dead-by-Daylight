# 格区调度台

一个 React 回合制格子对局，支持单人演练和好友联机。

```powershell
npm.cmd ci
npm.cmd run dev
```

打开终端显示的本地地址。在开局弹窗选择工作风或游戏风，再选「单人演练」、角色、人机难度和技能模式。点击「开始演练」后，在地图上选择出生点。轮到你时，点地图上的高亮格子移动。点灯、放板、砸板、翻越、撤离、等待和可用技能列在行动面板中。翻越和撤离也可直接点地图。完整规则可以从页面顶部打开。

开局可以选择普通、困难或地狱。技能模式可选无技能、2 技能或 3 技能。单人演练和战役中，双方各从本角色的 5 项技能里选取，电脑会自动配置技能并根据当前局面使用主动技能。开局后，对局状态面板会显示双方的技能和主动技能剩余次数。眩晕每剩 1 回合，角色就跳过 1 次自己的行动。

屠夫界面及电脑屠夫共用同一份可见状态。人类的位置、具体亮起的灯和行动明细会隐藏。屠夫在试图通过已放下的木板或被木板砸晕时，才会发现板已放下。

场地四周围墙，C2 和 C4 是内部墙段，C3 是窗户。C1 和 C5 的木板开局靠在通道左上端，放下后往右下搭住通道。点亮 3 盏灯后，在 A3 点击西门或在 E3 点击东门即可离开地图。

对局结束后可查看本局回放。从双方出生位置开始，用「上一回合」「下一回合」查看每回合结束时的地图和双方坐标。浏览器只保存最近一局已结束的回放，可从开局弹窗重新打开。中途返回配置不会覆盖已有记录。

## 好友联机

保持前端终端运行，在第二个终端启动房间服务。

```powershell
npm.cmd run online:server
```

在两个独立浏览器标签页打开前端，分别在开局弹窗选择风格和「好友联机」。一方创建房间，另一方输入六位房间码加入。房主先选角色和技能模式，双方各从本角色的 8 项技能中选满本局所需的数量。来宾确认准备后，房主点击「开始对战」。双方的技能配置在开局时公开。

刷新原标签页或短暂断网时，页面会尝试自动重连。对手断线时对局暂停，服务端检测到断线后会保留座位 10 分钟。主动退出会关闭未结束的房间。结算后双方均可逐回合查看完整回放。双方在线时，房主可以点击「设置下一局」，沿用房间码重新选择角色和技能。浏览器会用本局覆盖上一局回放。

### 在 Render 部署

仓库根目录的 `render.yaml` 会在新加坡创建一个免费 Node.js Web Service。它同时提供 React 页面和 `/online` WebSocket。同域部署无需填写 `VITE_ONLINE_URL`，默认允许 Render 分配的域名连接。

1. 打开 [Render 控制台](https://dashboard.render.com/)，选择 **New → Blueprint**。
2. 连接 `xcymm3/Dead-by-Daylight` 仓库，选择 `main` 分支，使用根目录的 `render.yaml`。
3. 确认预览显示一个新加坡 **Free Web Service** 后，点击 **Deploy Blueprint**。
4. 服务显示 **Live** 后，打开它分配的 `https://…onrender.com` 地址。访问同域的 `/healthz` 应显示 `ok`。再用两个浏览器进入首页，创建和加入同一个房间以验证联机。

如已有按旧说明创建的 Render 服务，也可以在其设置里将构建命令改为 `npm ci --include=dev && npm run build`，启动命令改为 `node server/index.js`，健康检查路径改为 `/healthz`。清除旧的 `VITE_ONLINE_URL`、`ONLINE_PORT` 和 `ONLINE_ORIGINS`，保存后重新部署。使用自定义游戏域名时，可用 `ONLINE_ORIGINS` 指定实际访问的 HTTPS 来源，多个来源用英文逗号分隔。

免费实例空闲约 15 分钟后会休眠，下一次访问需要等待唤醒。房间和进行中的对局存放在服务进程内存中，休眠和部署重启都会清空它们。回放保存在浏览器中，并按站点域名存储。

```powershell
npm.cmd test
npm.cmd run build
```
